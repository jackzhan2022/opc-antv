# 创作者合同模块

2026-11-14，已部署版本 `20261114-creator-contracts`，创作者数据库V4。腾讯企业接入参数尚未配置，尚未完成真实电子签联调；原文件导入和合同页面已上线。

## 已实现的流程

创作者详情增加「合同记录」，侧栏增加「合同管理」与「合同模板」。同一创作者可拥有多份独立合同，不为外部创作者创建内部登录账号。

1. 管理员导入 `.doc`、`.docx`、`.pdf` 模板原文件，单文件上限 5MB。原文件、摘要和元数据真实入库，可受控下载。检查文件扩展名和文件头；docx 检查必要条目、解压总量与宏文件。导入不会自动启用模板。
2. 管理员打开配置页。PDF 通过 UploadFiles 上传；Word 通过 CreateFileConvertTask 转换，并通过 DescribeFileConvertTask 取得 PDF 资源，再以 CreateEmbedWebUrl 的 CREATE_TEMPLATE 打开腾讯编辑页。转换状态持久化，未过期的同一转换任务不会反复上传。
3. 在腾讯编辑页核对 Word 转换后的字体、分页，配置公司与创作者两个签署方、填写控件和签章位置，并发布模板。回到平台「关联模板」，输入腾讯模板编号，服务端查询并校验后启用。可关联当前企业已经存在的普通模板。
4. 在创作者档案拟定合同，核对实名姓名、手机号、填写字段与签署截止日期。参考报价不会自动作为合同金额。草稿可编辑，版本冲突返回409。创作者归档后不能拟定新合同或发起签署，历史合同仍保留。
5. 草稿可生成填充后的预览。预览使用临时流程，不会 StartFlow，不把临时 FlowId 记录为正式合同。会消耗腾讯预览服务份额，页面明确确认。预览链接缓存五分钟；异步 DocumentFill 可回填结果，修改草稿会清除旧预览。
6. 管理员确认真实合同发起，后端执行 CreateFlow、CreateDocument。保存中间阶段后等待文档合成，通过后台任务或主动同步执行 StartFlow。公司和创作者各自手动签署，按模板的有序/无序设置发起；不是授权签、自动盖章或内部审批引擎。
7. 取得对应创作者的小程序签署链接，由内部人员通过自己的沟通渠道交给本人。平台不自动发消息，也不引入外部账号登录。
8. 加密签名回调同步状态，主动查询补偿。已完成签署的合同可下载最终PDF并归档到独立业务数据库，随后下载使用本应用鉴权。受控文件响应与合同API不缓存。

模板配置支持发起方文本、多行文本、日期、选择、勾选等控件；暂不接入动态表格、图片附件等复杂发起方控件。第一版仅接受依次为企业与个人的两个角色、已发布启用的普通手动签署模板，不接入企业授权签或医疗个人授权签。模板已有关联合同时，在本平台禁止直接编辑其腾讯模板，应导入新文件作为新模板。外部控制台改版会在发起时校验 TemplateVersion，阻止旧草稿静默使用新模板。

Word/PDF 文件不是自动识别的业务模板。Word 中的 `{{姓名}}` 等文本不会被当作已配置控件，扫描PDF也不会自动OCR；导入后需要在编辑页明确字段和位置。

## 权限与数据

- 使用创作者平台现有 OAuth2 登录、应用授权内省和 CSRF。所有启用且有应用权限的内部成员共享合同数据，可拟定/编辑草稿、预览、查看状态、取得签署链接和归档已签文件。
- 仅 ADMIN 导入/关联/停用模板、正式发起与撤销合同。ADMIN 平台权限不等于电子签印章权限，腾讯操作人和公司签署人必须分别具备真实的腾讯资源权限。
- 使用后端配置的企业操作人调用API，公司签署人由独立参数明确指定；内部操作人写审计，不假冒为腾讯员工身份。暂不做每位内部成员与腾讯员工的映射或授权签。
- V4 为创作者独立数据库的增量迁移，不是统一平台的 V4。新增 contract_template、creator_contract、contract_audit、contract_callback，旧V1—V3不变。保存模板版本、控件定义、创作者资料及公司身份快照，不依靠当前档案覆盖历史合同。
- 源文件上限5MB，最终PDF上限20MB，暂存业务库BLOB。列表查询不加载文件正文；备份需覆盖这些新表。后续量增可迁往私有对象存储，不能把腾讯临时URL当作永久归档。
- 不包含履约、付款、结算、批量合同、解除协议UI、复杂审批或自定义角色。已签合同无法直接撤销；已解除状态可从腾讯回调/查询同步。

## 腾讯接入配置

只在服务器环境变量或忽略的配置文件中填写，不能写入源码、浏览器存储、日志或聊天消息。

| 环境变量 | 用途 |
| --- | --- |
| CREATOR_ESS_ENABLED | 默认false。接入参数齐备后才设置为true |
| CREATOR_ESS_ENVIRONMENT | test 或 online，默认test。前端明确提示联调合同无法律效力 |
| CREATOR_ESS_SECRET_ID / CREATOR_ESS_SECRET_KEY | 当前环境的 API 凭证 |
| CREATOR_ESS_OPERATOR_ID | 当前企业中有API及相关模板/合同权限的操作人UserId |
| CREATOR_ESS_COMPANY_NAME | 公司签约主体的工商全称 |
| CREATOR_ESS_SIGNER_ID | 本公司真实签署员工的UserId，需具备相应印章使用权限 |
| CREATOR_ESS_CALLBACK_TOKEN | 腾讯配置的签名验证token |
| CREATOR_ESS_CALLBACK_KEY | 腾讯配置的AES-256回调密钥，UTF-8编码32字节 |

回调配置为 `https://x.aixmax.cn/creator-api/contracts/callback`（实际部署域名以生产配置为准），同时开启消息加密和签名验证。仅此POST入口免平台登录和CSRF，服务端始终校验原始请求体HMAC后才解密，不接受明文回调。其他合同API继续执行逐请求平台内省与CSRF。

测试/生产的模板绑定、合同和公司快照保存环境标识，禁止跨环境混用。通用API和文件上传分别使用官方域名，浏览器不能指定请求域名。使用Java标准HTTP客户端与TC3-HMAC-SHA256，错误只映射为内部代码，不返回腾讯异常消息、密钥或请求体。

## 网络失败与回调

腾讯当前 CreateFlow、CreateDocument 的 ClientToken 已注明不再使用，本实现没有依赖该字段提供远端幂等。

- 用户确认后先以版本号原子地把草稿改为PREPARING；重复点击不能再次发起。
- CreateFlow调用前持久化 CREATE_IN_FLIGHT，发送关联的内部合同ID与随机launch token到UserData。若响应丢失或进程中断，暂停自动创建，不盲目重放；验签回调携带对应标识时可关联实际FlowId并继续。若腾讯没有发出足够信息的回调，需要管理员联系技术人员核对腾讯记录，不能仅点击重新创建来猜测结果。
- CreateDocument调用前记录 DOCUMENT_IN_FLIGHT，发生不确定结果时，仅在查询证实合同已关联预期模板或收到 DocumentFill 后继续；不直接重复创建文档。
- StartFlow前先查远端状态，已经进入签署/完成的流程不再重复启动。文档合成成功后应尽快发起，遵守腾讯文档的五分钟要求。后台任务默认每十五秒处理，优先PREPARING；当前仍是单实例任务模型，不支持并行部署多个创作者实例。
- 回调使用MsgId去重，验签、解密和数据库提交完成后返回200，不在回调中调用耗时外部API。完成、拒签、撤销、过期等状态不会被迟到的中间状态覆盖，完成后允许转为已解除。未支持的回调类型确认接收但不改变本地业务。
- 回调表只存消息ID、类型与时间，不存包含个人资料的完整明文。审计记录操作类型和内部操作人，不复制签署密钥或签署链接。
