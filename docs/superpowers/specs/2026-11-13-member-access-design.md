# 成员管理与关联后登录

用户已确认采用手动成员管理，并明确要求外部身份先关联平台成员才允许登录。本次按该方案开发，统一平台和创作者平台仍分别部署。

## 已确认的行为

- 企业授权仅用于验证身份，不代表授予平台访问权。未关联身份记入待关联账号，跳回登录页并说明联系管理员；不创建平台成员，不签发已认证会话。
- 管理员预建成员并指定 ADMIN / MEMBER、启用状态，再将经过核对的待关联身份绑定到成员。一个成员可有飞书和企微身份。
- 普通成员不能读取或操作成员、待关联账号和审计接口。
- 平台显示名由管理员维护；上游姓名只保存在对应身份中，不覆盖平台显示名。
- 修改角色、停用、解除关联会递增成员会话版本；全部旧会话在后续请求失效。重新启用不会恢复旧会话。
- 最后一位启用管理员不可被停用或降级，也不可失去其最后一个可用登录身份。通过数据库守卫行锁串行化管理员变更，避免并发绕过。
- 同一个渠道身份只属于一个成员；同一个成员在同一个渠道及企业下至多有一个身份。重新关联必须先明确解除原关联，不隐式转移或合并权限。
- 成员创建、编辑、关联、解除关联及初始管理员建立均保存操作日志，不保存授权码、令牌或密钥。

## 页面和接口

沿用白色顶部导航，无侧边栏。管理员新增「成员管理」入口，页面包含成员、待关联账号、操作记录三个标签。成员可搜索、查看身份、创建和编辑；身份关联弹窗明确展示来源账号与目标成员。仅展示用户做决定所需文字。

- GET /api/admin/members?q=&page=1：分页成员，含关联身份。
- POST /api/admin/members：创建成员。
- PATCH /api/admin/members/{id}：修改姓名、角色和启用状态。
- GET /api/admin/pending-identities?page=1：分页待关联账号。
- POST /api/admin/pending-identities/{id}/bind：将待关联身份绑定到指定成员。
- DELETE /api/admin/members/{memberId}/identities/{identityId}：解除关联，回到待关联列表。
- GET /api/admin/audit?page=1：分页操作日志。

以上写接口要求管理员身份及 CSRF，失败返回明确错误码，操作原子提交。列表每页20项，关联目标通过服务端搜索获取，已停用成员不能接收新关联。

## 初始管理员与升级

初始管理员由显式的 SINX_BOOTSTRAP_* 部署配置指定 provider、tenant、subject、displayName，可指定已有 memberId。启动时只运行一次受审计的预关联初始化，不根据首次登录、姓名或旧 ADMIN_SUBJECTS 推断权限。数据库记录初始化完成，之后重启不会重新提权。

V2 将旧版自动登记的外部身份转为待关联，保留原成员记录，避免历史自动注册变成未经确认的授权。部署前备份独立数据库，并从已核实的既有成员记录提取初始管理员身份；不输出 subject 或任何凭据。启动后撤下临时初始化配置。旧服务重启后内存会话失效。

## 验证

后端测试覆盖：未关联不建成员、重复登记幂等、已关联登录、双渠道同一成员、企业隔离、角色鉴权、CSRF、最后管理员保护、关联冲突、停用及重新启用不恢复会话、权限变化使旧会话失效、审计和一次性初始化。H2 默认回归并在本机专用 MySQL 测试库验证迁移，禁止清理型测试指向正式数据库。

前端测试覆盖：未关联提示、普通成员无管理入口、匿名/普通成员拒绝管理页、创建/编辑、关联/解除关联、错误提示、分页和窄屏不溢出。生产只执行无清理的健康检查和真实企业登录验收。
