# OPC 内部创作者管理平台技术选型

> 确认日期：2026-11-13。本文区分已确认主技术路线、推荐配套和待确定事项；技术路线确认不等于应用已经实现，也不代表需求草案中的全部功能已获批准。

## 一、已确认主技术路线

用户已确认沿用 `ant_short_TV` 的以下技术：

| 层面 | 已确认选择 | 在本项目中的用途 |
| --- | --- | --- |
| 前端 | React + Umi | 内部运营后台、页面与路由组织 |
| UI | Ant Design | 列表、筛选、表单、详情等后台界面 |
| 后端 | Java + Spring Boot | 业务接口、权限校验和事务处理 |
| 数据库 | MySQL | 创作者档案、职业关联、跟进与合作等结构化数据 |
| 文件存储 | 腾讯云 COS 私有对象存储 | 作品、图片、视频和业务附件 |

选择这条路线是为了沿用参考项目的工程经验，减少维护不同技术体系的成本。Ant Design 是 UI 组件库；AntV 图表库不是已确认的基础依赖。

## 二、与参考项目的关系

参考项目已通过依赖配置与源码抽样核实为 React/Umi 企业后台与 Java Spring Boot 后端，使用 MySQL、MyBatis-Plus、Flyway、Cookie Session 与私有 COS。关键核查位置为参考项目的 `frontend/package.json`、`backend/pom.xml` 及认证、项目筛选和上传模块。

以上核查不代表参考项目已通过本次构建、测试或线上运行验证；也不构成本项目对参考项目源码目录的运行依赖。

### 适合借鉴的工程模式

- 使用表格、搜索表单、弹窗编辑和详情页组织标准后台业务。
- 类型化请求封装、统一响应与错误处理。
- 在后端按授权范围筛选数据，再执行分页与总数统计。
- 参数校验、事务处理、增量数据库迁移和权限测试。
- 附件上传授权、完成校验、业务记录绑定与受控读取。

### 不直接照搬的内容

- 短剧、分镜、视频处理、AI 生成、点数计费、支付与小程序业务。
- 与新平台无关的历史数据库迁移和模板示例。
- 未经本项目需求确认的复杂多租户或多层级权限。
- 参考项目的账号、会话、业务表、存储凭据或生产配置。

建议新平台独立建模、独立管理数据库迁移和 COS 对象访问边界；是否共享基础设施另行确定。

## 三、推荐配套（尚未锁定）

以下是围绕已确认主技术路线的推荐，不应当作已安装或已批准的完整依赖清单。

| 领域 | 推荐配套 | 适用边界 |
| --- | --- | --- |
| 前端工程 | TypeScript + Umi Max | 沿用参考项目的后台路由、布局与请求组织模式 |
| 业务组件 | ProComponents | 列表与表单优先复用组件，先验证与 Ant Design 的兼容性 |
| 状态与请求 | Umi request、initialState/model、React hooks | 复杂服务端状态按需使用 React Query，不默认叠加多套状态库 |
| 样式 | Ant Design 主题 + CSS Modules | 优先使用统一组件与主题，不默认叠加多套样式框架 |
| 数据访问 | MyBatis-Plus + Flyway | 明确 SQL 数据范围，使用增量迁移维护数据库 |
| 认证权限 | Spring Security + 可撤销 Cookie Session + CSRF | 后端执行权限；若接入企业单点登录，需要适配身份来源 |
| 表格导入导出 | Apache POI | 后端执行权限校验、数据校验和疑似重复提示 |
| 前端质量 | Vitest + Testing Library + Biome | 覆盖组件行为、请求边界与格式检查 |
| 后端测试 | JUnit + MockMvc + 数据库集成测试 | 核心 SQL 和迁移需验证 MySQL 行为，不能只依赖 H2 替代环境 |
| 部署 | Nginx + 前端静态文件 + 后端 JAR | 作为初期简单部署方案，最终按实际运行环境确定 |

版本基线建议优先保持与参考项目相近的兼容组合，但必须检查维护状态、安全更新与依赖兼容性。Java 17 可作为候选基线，具体 JDK、Node.js、Spring Boot、Umi、React、Ant Design 和 MySQL 版本尚未锁定。参考项目的 Spring Boot 3.3.5 等历史版本不是本项目的自动选定版本。

## 四、推荐架构与业务边界（尚未实现）

已确认统一平台与创作者平台独立建设，各自前后端、数据库与部署；可各占一个仓库。每个系统内部采用前后端分离与模块化单体，通过协议或 API 协作，不跨系统直接写库。

建议业务模块包括账号与权限、创作者档案、作品与附件、运营跟进、轻量项目合作、基础字典和审计。模块是否全部进入第一版，仍以需求确认结果为准。

建模时保留以下边界：

- 内部账号与外部创作者档案分开，不默认向每位创作者开放登录。
- 常用筛选字段、职业及技能关联使用明确字段或关系表；少量职业专属扩展信息可考虑校验后的 JSON。
- 运营跟进是独立业务记录，不使用技术审计日志代替。
- 资源阶段、接单状态与项目合作状态分别建模。
- 私有 COS 不等于业务授权；后端仍需校验文件归属与访问权限。数据库保存对象标识和元数据，不将临时签名 URL 作为永久业务值。
- 参考项目主要面向媒体的上传白名单，不能直接覆盖本项目可能需要的 PDF、Word 等附件；需按实际业务确定允许类型、大小限制和下载策略。

## 五、暂不作为默认基础设施的内容

在出现明确需求或性能证据前，建议不引入微服务、Kubernetes、Redis、消息队列、Elasticsearch、复杂工作流引擎或智能匹配服务。此处是控制首版复杂度的建议，不是永久禁止扩展。

## 七、当前落地状态（2026-11-13）

已在 sinx-platform/ 创建统一平台独立前后端：React 18.3.1 / Umi 4.7.32 / Ant Design 5.29.3，Java 17 / Spring Boot 4.0.9 / Spring Security / JDBC / Flyway / MySQL。其余推荐配套仍按实际需要选择，本期未引入 MyBatis-Plus、COS 或共享 Session 基础设施。

已实现飞书与企业微信登录适配、平台会话、工作台、退出，以及手动成员管理与身份关联。未关联的已验证身份存入 pending_identity，经管理员关联后才能登录；使用 session_version 撤销角色或身份变更前的会话，管理员写操作和身份登记由 MySQL 行锁串行化，操作日志同事务入库。V2 增量迁移保留旧成员并将旧自动注册身份转入待关联，需明确初始化首位管理员。

统一平台已部署到 x.aixmax.cn，企微真实登录、会话刷新、退出与匿名拦截已验证；新成员管理版本的发布及真实验收状态见服务器部署记录。飞书尚未配置。服务器使用 Nginx 静态前端、Java 17 独立 systemd 服务与 MySQL 8.0.46 独立容器，后台和数据库仅监听 localhost。提供正式构建产物的浏览器测试、后端鉴权与并发事务测试、H2及独立 MySQL 迁移验证。已新增独立creator-platform工程与OAuth2授权码+PKCE跨系统登录，未引入通讯录同步或自动匹配；运行边界、依赖审计及密钥轮换待办见 [../sinx-platform/README.md](../sinx-platform/README.md) 和服务器部署记录。


创作者第一版沿用相同前后端技术栈，以独立MySQL业务库、独立systemd服务部署在 `/creators/` 与 `/creator-api/`。统一平台增加Spring Authorization Server，使用授权码+PKCE和opaque token，创作者后端逐请求内省成员状态及版本；不共享Cookie和写库账号。作品仅保存链接，本期不接COS或文件上传。单实例内存会话的运行限制继续适用。

创作者结构对齐增加独立dictionary模块与V2配置表/审计表/事务守卫，配置写入及档案保存共用守卫锁；V3仅增量添加简介、DECIMAL(12,2)报价及单位。统计与列表共用过滤条件，近7日按updated_at计算。前端独立业务壳层、管理员配置静态路由、URL上下文返回，与统一平台工程无新增耦合。更新脚本只发布创作者产物，在私有端口先验证迁移及旧业务数据，完成后切换正式服务，保留统一平台配置与进程。
